# ADR-0004: SDUI هجين: سجل كتل مطبوعة، وشاشات تجارة أصلية

- الحالة: مقترح
- التاريخ: 2026-11-10
- مرتبط بـ: ADR-0006, F-M03

## السياق
يجب أن يغيّر التاجر الرئيسية وصفحات الحملات دون إصدار جديد للتطبيق. ومكتبات SDUI العامة في Flutter إما غير ناضجة لصفحات التجارة، أو متوقفة، أو تقرّ بأن التوافق مع الإصدارات القديمة «best-effort». ويكشف كود عناقيد أن تخزين الإعدادات مفاتيح مسطحة يولّد 146 إلى 214 زرًا للقسم الواحد.

## القرار
1. **مستوى الأقسام لا العناصر الأولية**: سجل كتل مكتوب يدويًا في Dart (`hero_slider` و`product_carousel` وغيرهما). لكل كتلة نوع، ورقم إصدار، وإعدادات عرض محدودة، ومصدر بيانات، وقواعد ظهور.
2. **الصفحات الحرة**: الرئيسية، وصفحات الحملات، ورؤوس التصنيفات.
3. **الشاشات الأصلية** (صفحة المنتج، والسلة، والحساب، والبحث) لا تُبنى من كتل حرة، بل تُضبط بقائمة وحدات يرتّبها التاجر ويُخفيها، وبالـ tokens.
4. **التوافق**: يرسل التطبيق `X-App-Version` وقائمة الكتل التي يعرفها بإصداراتها، ويُسقط الخادم ما لا يستطيع التطبيق رسمه. والنوع المجهول يُرسم فارغًا ويُسجَّل حدث `unknown_block`. وكل كتلة داخل حاجز أخطاء.
5. **الأفعال قائمة مغلقة**: `open_product` و`open_category` و`open_page` و`open_url_inapp` و`add_to_cart` و`apply_coupon` و`share` و`search`، ويمر كلها عبر موجّه واحد يخدم الروابط العميقة أيضًا.
6. **العقد**: لكل نوع كتلة JSON Schema في الخادم يُتحقق به عند الحفظ. لا يُعاد استخدام حقل لمعنى آخر، ولا يُضاف إلا حقل اختياري.
7. حزمة `storefront_ui` بـ Dart خالص، تُبنى للجوال ولمعاينة Flutter Web.

## البدائل المرفوضة
- **Stac أو rfw كمحرك عام**: تُستعار أنماطهما (السجل، ومحللات الأفعال، والتخزين المؤقت) دون الارتهان لهما.
- **إعدادات مسطحة في Remote Config**: هذا ما أنتج إغراق التاجر عند عناقيد.

## العواقب
- إضافة نوع كتلة جديد تحتاج إصدارًا للتطبيق. أما تغيير ترتيب الكتل ومحتواها وظهورها فلا يحتاج.
- مساعد الذكاء الاصطناعي آمن، لأنه لا يكتب إلا JSON يتحقق منه المخطط.

## تعديلات 2026-11-10 من مواصفات الوحدات

1. **مكان مخططات الكتل:** المصدر الوحيد هو `06-api/blocks/`. وتستهلكه مستودعات الكود كـ git submodule مثبّت على tag. يُتحقق منه في PHP بـ opis/json-schema وفي TypeScript بـ Ajv، وتُولَّد أنواع TypeScript، أما نماذج Dart فتُكتب يدويًا وتحرسها اختبارات العقد ([M03](../modules/M03-blocks-pages.md)).
2. **صيغتان للصفحة:** صيغة تحرير تحفظها اللوحة، وصيغة تسليم يرسمها التطبيق، وهي مترجمة ومعبأة بالبيانات.
3. **الأفعال:** `add_to_cart` و`apply_coupon` متاحان للكتل فقط، ولا تستدعيهما الروابط الخارجية ولا الإشعارات ([M07](../modules/M07-deep-links.md)).
4. **إعداد الشاشات الأصلية:** وثيقة `shell` واحدة تضم وحدات صفحة المنتج، ونمط البطاقة، والشريط السفلي، والشريط العلوي.
