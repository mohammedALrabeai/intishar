# إجراء طلب التغيير (Change Request)

بعد اعتماد أي وثيقة (🟢)، لا تُعدَّل مباشرة. يمر كل تغيير بهذا الإجراء، حتى لا يتسع النطاق بقرارات فردية أثناء التنفيذ.

## توضيح أم تغيير؟

| توضيح (لا يحتاج طلب تغيير) | تغيير (يحتاج طلب تغيير) |
|---|---|
| سؤال عن معنى معيار قبول موجود | إضافة ميزة أو حذفها، أو تغيير أولويتها |
| حالة حدية لم تُذكر، وجوابها لا يغيّر السلوك العام | تغيير سلوك متفق عليه أو تصميم معتمد |
| خطأ إملائي أو رابط مكسور | تغيير قرار معماري (يتطلب ADR جديدًا) |
| — | أي شيء يغيّر المدة أو يؤثر في ميزة أخرى |

التوضيح يُجاب في جلسة ترتيب الـ Backlog (Refinement)، ويُضاف إلى القصة.

## الخطوات

1. **الفتح**: Issue بعنوان `CR-xxx: …` بالقالب أدناه، ويمكن أن يفتحه أي عضو في الفريق.
2. **تحليل الأثر**: يكتبه المشرف مع المنفذ: على النطاق، والمدة، والمزايا الأخرى، والمخاطر.
3. **القرار**: المعتمِد يقبل الطلب، أو يرفضه، أو يؤجله إلى إصدار لاحق. وإن لم يمس الطلب النطاق ولا المدة، يكفي قرار المشرف.
4. **التنفيذ إن قُبل**: تُحدَّث الوثائق المعنية في Pull Request، ويُرفع رقم الإصدار الفرعي للمواصفات (مثل `spec-v1.1`)، ثم تُنشأ القصص الجديدة أو تُعدَّل.
5. **التسجيل**: في سجل التغييرات أدناه.

## قالب الطلب

```markdown
## CR-xxx: العنوان
- مقدّم الطلب:
- التاريخ:
- الوثائق أو المتطلبات المتأثرة: F-xx, ADR-xxxx, ...

### ما التغيير المطلوب؟
### لماذا؟
### الأثر (يكتبه المشرف)
- النطاق:
- المدة:
- المزايا الأخرى:
- المخاطر:
### البدائل
### القرار
قبول | رفض | تأجيل — التاريخ — بواسطة
```
