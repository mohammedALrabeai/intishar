# قرارات المنتج

> آخر تحديث: 2026-11-10

### D-02: اعتماد نطاق الإصدار الأول
- **المطلوب**: مراجعة القسم 5 في [PRD](01-prd.md)، وتأكيد ما هو Must أو نقله إلى Should. مع منفذ واحد، كل Must إضافي يطيل المرحلة 3 مباشرة.
- **التوصية**: الإبقاء على القائمة كما هي.

### D-05: خدمة CI لبناء التطبيقات
- **الخيارات**: Codemagic، ولها مسار white-label موثق، وتكلفة macOS M2 نحو 0.095 دولار للدقيقة. أو GitHub Actions مع fastlane، بتكلفة نحو 0.062 دولار للدقيقة، لكن مع صيانة سكربتات التوقيع وإعادة التسمية.
- **التوصية**: Codemagic، لأن المنفذ واحد ووقته أغلى من فرق الدقائق. والحسم النهائي بعد قياس SPK-13.

### D-06: الاستضافة ومنطقتها
- **المطلوب**: مزود السحابة ومنطقته لخادم Laravel وتطبيق Next.js وقاعدة البيانات والـ CDN.
- **التوصية**: مزود له منطقة داخل المملكة أو قريبة منها، لأن معظم المتسوقين في السعودية.

### D-07: تاريخ البدء ونسبة التفرغ
- **لماذا**: تحويل الأسابيع النسبية في [خارطة الطريق](roadmap.md) إلى تواريخ فعلية في صفحة التقدم.

### D-08: مصدر التصميم دون مصمم
- **المشكلة**: لا يوجد دور مصمم، والمنفذ ليس مصممًا، وتجربة المستخدم أولوية.
- **التوصية**:
  - **لوحة التاجر**: shadcn/ui (ضمن ADR-0010) هو نظام التصميم نفسه، وله ملف Figma رسمي. التصميم يتم بتركيب مكوناته، لا برسم من الصفر.
  - **تطبيق المتسوق**: شراء مكتبة Figma جاهزة لتطبيق تجارة إلكترونية بجودة عالية، يكيّفها المشرف على الـ tokens والهويات الجاهزة، ويصمم بها الشاشات الأساسية بحالاتها. ثم يصبح كتالوج مكونات `storefront_ui` في Widgetbook هو المرجع الحي بعد بنائه.
  - **البديل**: مصمم مستقل بعقد قصير لتصميم الهويات الجاهزة وشاشات التسوق فقط.

### D-09: أداة تتبع المهام
- **التوصية**: GitHub Issues وProjects في مستودع خاص باسم `intishar`. فيه لوحة Kanban وعرض Roadmap دون تكلفة، ويُربط كل PR بمهمته، وتقرأه بوابة المشروع آليًا (ADR-0001).
- **الحسم**: أُنشئ المستودع الخاص، واستُوردت إليه مهام المرحلة 0 ونقاط المراجعة، وحُذف الملف المؤقت. وطريقة التحديث في [roles.md](process/roles.md#تحديث-حالة-المهام).

### D-10: اعتماد القرارات المعمارية
- **المطلوب**: قراءة [سجل الـ ADRs](adr/README.md). كل قرار لا اعتراض عليه يتحول من «مقترح» إلى «مقبول».
